# 小说库相似度比对服务工作区

## 1. 工作区定位

本工作区用于单独开发“小说库数据接入与相似度比对服务”。

该服务不是当前桌面工具 `侵权巡检助手` 的一个普通功能页，而是一条独立主线。它的职责是：

- 接收字幕文本或字幕分段
- 接入公司小说库数据
- 建立检索与比对索引
- 输出候选书籍、候选章节、证据片段和复核结果

当前将它从桌面工具主仓拆出去，目的是避免继续把三类工作混在同一个工作区内：

- 法务前置处理工作台
- 素材投放视频分析工作台
- 小说库相似度检索服务

## 2. 当前拆分结论

当前桌面工具继续负责：

- 视频链接采集
- 视频下载
- 音频抽取
- ASR 转写
- 字幕导出
- 片段截取
- 后续的视频分析模型接入

本服务单独负责：

- 小说库数据接入
- 数据清洗和标准化
- 索引构建
- 相似度召回与精排
- 证据片段输出
- 人工复核结果沉淀

## 4. 本工作区起步顺序

1. 先确认公司小说库的实际交付形式
2. 先做样本库验证，不直接接入 10 多万本全量
3. 先跑通“字幕输入 -> 候选召回 -> 证据输出”
4. 再做全量索引、增量同步和桌面端联调

## 5. 对当前桌面工具的关系

桌面工具是这个服务的上游，不是这个服务的宿主。

推荐联动方式：

- 桌面端导出 `subtitle_text + subtitle_segments + source metadata`
- 通过接口提交到本服务
- 本服务返回候选结果和证据片段
- 桌面端只展示结果摘要和跳转链接

## 7. 新旧项目关系

- 旧项目：`侵权巡检助手`
  - 形态是桌面工作台
  - 负责视频采集、下载、音频抽取、ASR、字幕导出、片段截取、后续视频分析
- 新项目：`小说库相似度比对服务`
  - 形态是独立后端服务
  - 负责小说库接入、数据清洗、索引、召回、精排、证据输出、复核状态沉淀

两者关系不是“一个仓库拆子模块”，而是“上游工作台 + 下游比对服务”。

边界上要坚持三点：

- 新项目不承载桌面 GUI
- 旧项目不承载全量小说库与检索索引
- 两边通过字幕结果和接口协议对接

## 8. Web V1 本地联调

当前 `Web V1` 已支持真实接口联调，最小本地启动方式有两种。

### 方式一：一键开发模式

适合当前阶段前后端联调。

- 运行：`powershell -ExecutionPolicy Bypass -File .\scripts\run_web_v1_dev.ps1`
- 效果：
  - 启动 `uvicorn api.app:app`，监听 `http://127.0.0.1:8000`
  - 启动 `web` 的 Vite dev server，监听 `http://127.0.0.1:4175`
  - 自动开启 API 内嵌 worker，本地创建的批量任务会自动从 `queued` 被消费

### 方式二：分开启动

适合需要单独观察 API 或 worker 日志时使用。

1. 启动 API：

```powershell
$env:NOVEL_SIMILARITY_AUTOSTART_WORKER='0'
python -m uvicorn api.app:app --host 127.0.0.1 --port 8000
```

2. 单独启动 worker：

```powershell
python .\scripts\run_task_worker_v1.py
```

3. 启动前端：

```powershell
cd .\web
npm.cmd run dev
```

### 本地联调说明

- 前端 dev server 已通过 `vite.config.ts` 代理 `/api` 到 `http://127.0.0.1:8000`
- 批量任务上传目录默认是 `runtime/task_uploads`
- 批量任务导出目录默认是 `runtime/task_exports`
- 如果只想让 API 在本地自动消费任务，可设置：
  - `NOVEL_SIMILARITY_AUTOSTART_WORKER=1`
  - `NOVEL_SIMILARITY_AUTOWORKER_POLL_SECONDS=1.5`
