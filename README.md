# 小说相似度比对系统

一个面向短剧台词与小说正文比对的内部检索与复核系统。项目聚焦“文本证据可落地”的检测链路：输入短剧台词、批量线索表或采集侧导出的 Excel，系统完成候选召回、证据级精排、人工复核与结果导出，帮助业务侧快速定位高风险改编、复用或疑似改写内容。

当前实现并不只是一个单点比对页面，而是一条完整工作流：采集侧可以从短剧作者主页提取首集内容并转写台词，检测侧可以直接消费结构化表格，批量执行检索任务，并将复核结论以 Excel 形式沉淀下来，服务后续排查与维权流程。

## 核心能力

- 单条检测：输入一段台词或文本，返回候选小说、证据片段和相似度指标。
- 批量检测：导入 Excel 批量创建任务，支持进度跟踪、暂停、继续、取消、删除和结果汇总。
- 改写检测：在普通复用检测基础上叠加语义补召回，用于覆盖字面差异更大的场景。
- 人工复核：集中展示查询文本、候选证据、辅助指标和处理状态，支持按任务过滤与结果导出。
- 结果沉淀：支持按复核状态导出结构化表格，保留短剧名、集数、作者、命中小说、证据文本和处理结论。
- 采集表兼容：兼容项目内批量样表，也兼容上游采集工具导出的结构化 Excel。

## 方法概览

系统主链路采用“词法粗召回 + 证据级精排 + 语义补召回”的分层方案，而不是单纯依赖某一种检索方式。

词法层使用基于 `FTS5` 的章节级倒排索引，对输入文本做规范化与 trigram 拆分后先拉出候选集合，优点是快、稳定、对中文台词中的局部复用比较敏感。精排层再把候选章节切成证据窗口，逐窗计算最长连续匹配比例、n-gram 召回率、精确率、Jaccard、序列相似度等指标，输出真正可复核的文本证据。语义层则基于较长语义切片做向量补召回，用来覆盖改写更强、字面差异更大的样本。

为了兼顾证据展示和语义检索，项目维护了两套不同粒度的切分方式：

- `200/50` 证据窗口：用于精排、证据定位和前端展示。
- `800/200` 语义切片：用于 embedding 与向量检索。

向量库当前采用 `Qdrant`，语义向量使用 `Qwen3-Embedding-8B` 生成并落入独立 collection。业务主数据、任务状态、复核状态和索引元数据仍由 `SQLite` 承载，这样可以把“业务数据层”和“语义索引层”拆开，便于本地开发、问题排查和后续扩容。

## 项目结构

```text
api/        FastAPI 接口、运行时 worker 挂载
service/    检索、比对、任务执行、导出等核心服务逻辑
scripts/    数据导入、切分建库、向量回填、评测与运维脚本
tests/      Python 侧 smoke test 与解析测试
web/        React + Vite 前端
docs/       项目汇报、实验记录、问题复盘与阶段文档
data_samples/ 示例输入、评测样本与批量模板
```

## 本地启动

### 1. 安装依赖

后端依赖：

```powershell
pip install -r requirements-deploy.txt
```

前端依赖：

```powershell
cd web
npm install
```

### 2. 一键联调

项目内提供了本地联调脚本，会同时启动后端和前端。

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\run_web_v1_dev.ps1
```

默认启动结果：

- API: `http://127.0.0.1:8001`
- Web: `http://127.0.0.1:5173` 或 Vite 当前分配端口
- 本地 worker：由 API 自动拉起

### 3. 分开启动

如果需要单独查看日志，可以分开运行：

启动 API：

```powershell
$env:NOVEL_SIMILARITY_AUTOSTART_WORKER='0'
python -m uvicorn api.app:app --host 127.0.0.1 --port 8001
```

启动 worker：

```powershell
python .\scripts\run_task_worker_v1.py
```

启动前端：

```powershell
cd .\web
npm run dev
```

## 数据与环境说明

仓库中保留了部分样例、评测文档和工作记录，但不包含完整生产小说库，也不默认附带完整向量数据。要跑通语义召回，需要额外准备：

- 本地或远程可用的 `Qdrant`
- 可用的 embedding API 配置
- 已完成切分、建库和向量回填的数据集

如果只验证普通词法链路与前后端交互，不依赖完整语义库也可以启动系统，但改写检测会进入降级或关闭状态。

## 当前阶段

这个项目已经完成了从“线索采集 -> 台词转写 -> 批量检测 -> 人工复核 -> 结果导出”的可运行闭环，前端交互、批量任务管理、复核工作台和导出链路都已具备实际使用基础。现阶段最主要的上限不在页面或主链路逻辑，而在于可接入源数据的覆盖范围与上游数据质量。

换句话说，系统骨架已经搭起来了，后续扩展重点会更多落在数据接入、数据治理、向量回填和更大规模样本验证上。
