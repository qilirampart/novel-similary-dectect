# 云端短剧字幕 API 发布任务板

## 目标

将短剧字幕检索和三态最终判定能力部署到现有小说相似度服务云端，使 YouTube 字幕核验助手可通过 API 调用，不复制索引或业务数据到桌面端。

## 数据规模与安全措施

字幕 SQLite 原始大小约 2.85 GB，压缩后约 924 MB。4B Qdrant snapshot 约 3.70 GB。云端剩余磁盘约 125 GB，足够容纳数据、快照恢复和旧 release。

数据上传均写入独立临时文件或 `.parts` 目录，未完成时不会修改服务配置或 `current` 软链接。正式发布通过 release 目录和 `current` 软链接切换；上一版为 `/opt/novel-similarity-service/releases/20260707-resume-progress-baseline-sync-1`，可立即回滚。

## 发布结果

当前云端 release 为 `/opt/novel-similarity-service/releases/20260807-subtitle-normalization-consistency-sync-1`，上一版回滚目标为 `/opt/novel-similarity-service/releases/20260807-video-level-subtitle-api-sync-1`。短剧 SQLite 的 SHA-256 已与本地一致；Qdrant 4B collection 状态为 `green`，包含 309,138 个向量点。已使用登录态验证真实英文字幕：返回 `matched`，命中 `The Taming Game` 第 1 集，关联第 2 集；启用语义增强时状态为 `ok`，返回 20 个语义候选，但最终确认仍以词级强证据为准。

2026-08-06 已补充“内容命中”和“剧名归属”两维判定。对于 `Kissing the Wrong Brother` 与 `Falling for the Right Brother` 这类多个 `book_id` 存在大段连续台词复用的情况，接口返回 `content_match_status=matched`、`title_resolution=ambiguous`，前端显示“内容已命中，剧名待确认”。已使用真实 YouTube 字幕复测，返回两部强证据候选和明确原因文案，服务健康检查通过。

同日已补充强证据候选的复核优先级、文本命中率、证据覆盖率和语义相似度。批量列表不再仅显示“剧名待确认”，会直接列出可供确认的剧名；排序优先使用连续文本复用证据，语义相似度只作辅助。

同日进一步拆分覆盖率口径：`最佳片段覆盖` 是单个最佳证据窗口对整段输入的覆盖，继续用于保守的确认规则；`累计文本覆盖` 是同一集全部已召回窗口合并后的输入覆盖，仅用于展示和复核排序。真实英文字幕复测中，最佳片段覆盖约 36%，累计文本覆盖为 77.88%，最终判定没有变化。

累计覆盖首版会对全部 200 个原始词法窗口重新分词，实测会增加 17% 至 53% 的词法阶段耗时。已优化为只统计最终返回候选涉及的窗口，真实 1651 字符和 1140 字符样本相对旧单窗口统计的中位耗时变化分别为 -0.93% 和 +0.74%，均在约 11ms 的正常波动内。

2026-08-07 已发布视频级接口 `POST /api/v1/drama-subtitles/video-compare`。接口接收完整字幕和 cue 时间轴，服务端先完整字幕初筛，仅在未确认时 cue 对齐分段补检，并在出现确认结论时停止。真实英文字幕云端验证返回 `content_matched_ambiguous`，执行策略为 `fast_screen_only`，处理片段数为 0。详细接入说明见 `89_视频级字幕匹配接口接入说明_2026-08-07.md`。

同日修复入口文本规范化不一致：单条、批量和视频级接口均会移除 `[music]` 等方括号舞台标签后再执行词法和语义检索。`He tricked her into a divorce...` 原始字幕与 `Her Divorce, Her Triumph` 的剧情和对白顺序高度相似，但角色名和局部措辞不同，当前统一返回 `potential_match`（9 个共享四词短语、输入覆盖 6.77%、证据覆盖 16.07%），保留为待复核而不直接确认命中。
