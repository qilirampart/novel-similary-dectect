验证用户提供的 3 条短剧前三集文案，能否在当前正式全库中找到对应小说。

本次测试使用当前正式语义 collection：

- `novel_semantic_chunk_embeddings_qwen3_8b_1024_v1`

测试模式：

- `rewrite`

说明：

- 本次以当前正式全库 `rewrite` 链路为准
- 语义侧使用 Gitee API + `Qwen3-Embedding-8B`
- chapter 语义向量未参与本次测试，实际走的是“词面召回 + 正式 chunk 语义召回 + 候选融合 + 现切 + 细比对”

## 4. 结论

本次 3 条短剧前三集文案，当前系统都成功找回了对应小说。

而且不是只找回“同题材”或“同宫斗套路”小说，而是直接把同一本目标小说顶到了 top1，章节也和前三集顺序基本对上：

- 第 1 条 -> 章节 `1`
- 第 2 条 -> 章节 `2`
- 第 3 条 -> 章节 `3`

这说明当前正式全库 `rewrite` 链路，对这种“接近原文、按集拆分”的短剧文案已经具备较强可用性。

## 5. 当前仍需注意的点

虽然 3 条都命中了目标小说，但证据强度并不完全一致：

- 第 1 条和第 2 条仍是 `弱证据`
- 第 3 条达到 `中证据`

这说明当前系统的“找回目标小说”能力已经够用，但“最终证据标签”仍偏保守。换句话说：

- 粗召回和语义召回已经能把正确小说带回来
- 但细比对对这类短剧文案的判定还不够激进

因此，当前更合理的判断不是“这条链路找不到”，而是：

- “能找到”
- “能排到第一”
- “但前两条在最终证据分级上还不够强”

## 6. 测试过程中的一个修正

本次第一次执行时，语义链路曾回退为 `fallback_lexical_only`。原因不是检索逻辑问题，而是 Gitee API 调用时模型名误用了：

- 错误写法：`qwen3-embedding:8b`
- 正确写法：`Qwen3-Embedding-8B`

修正模型名后，3 条 query 均正常进入 `semantic_ready`，最终结果以上述第二轮复测为准。
