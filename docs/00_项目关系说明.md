# 新旧项目关系说明

## 1. 新项目是什么

新项目名称：

- 小说库相似度比对服务

工作区位置：

- `E:\点众\小说库相似度比对服务工作区`

它是一个独立服务项目，不是当前桌面工具中的一个新页面或一个附属脚本目录。

## 2. 之前项目是什么

之前项目是当前已经在开发中的桌面工具项目：

- 侵权巡检助手

主要源码位置：

- `E:\点众\自动化工具\侵权巡检助手工作区\源码`

相关文档位置：

- `E:\点众\自动化工具\侵权巡检助手工作区\文档`

与本服务直接相关的既有预案：

- `E:\点众\自动化工具\侵权巡检助手工作区\文档\小说库数据对接与相似度比对预案.md`

## 3. 两个项目为什么要拆开

`侵权巡检助手` 当前已经承载两条主线：

- 法务前置处理工作台
- 素材投放视频分析工作台

如果再把“10 多万本小说的全文接入、索引和相似度比对”继续堆进去，会同时混入第三条主线：

- 小说库相似度检索服务

这样会带来这些问题：

- 工作区定位混乱
- 客户端和服务端职责混乱
- 打包和部署方式混乱
- 桌面端改动和索引服务改动互相污染

因此必须拆开。

## 4. 两个项目的关系

两者关系应理解为：

- 旧项目是上游字幕生产工作台
- 新项目是下游相似度比对服务

数据流建议保持为：

`视频/片段 -> 侵权巡检助手 -> 字幕文本/字幕分段 -> 小说库相似度比对服务 -> 候选书籍/证据片段 -> 桌面端查看结果`

## 5. 职责边界

### 5.1 侵权巡检助手负责

- 视频链接采集
- 视频下载
- 音频抽取
- ASR 转写
- 字幕导出
- 片段截取
- 后续视频分析模型接入
- 向相似度服务提交字幕任务
- 展示比对结果摘要

### 5.2 小说库相似度比对服务负责

- 小说库数据接入
- 原始数据留档
- 标准化清洗
- 章节切分和滑窗切分
- 索引构建
- 粗召回
- 精排比对
- 证据输出
- 复核结果沉淀

## 6. 本项目不是旧项目的什么

本项目不是：

- 旧项目的一个子页面
- 旧项目的一个后台线程
- 旧项目的一个 `scripts/` 目录
- 旧项目里顺手加的一个检索模块

本项目是一个需要独立工作区、独立规则、独立部署方式的服务项目。

## 7. 当前协作原则

- 旧项目继续围绕桌面工作台推进
- 新项目只围绕相似度服务推进
- 两边通过输入输出协议对接，不交叉承载主逻辑
- 旧项目的业务变更，不默认迁入新项目
- 新项目的索引和服务逻辑，不反向塞回旧项目
