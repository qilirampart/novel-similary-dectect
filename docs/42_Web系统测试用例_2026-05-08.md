# Web系统测试用例

更新时间：2026-05-08

## 1. 测试概述

本轮测试用例面向当前“小说库相似度比对系统”Web 版本，目标不是做泛化 QA 模板，而是围绕当前已经实现且近期频繁暴露问题的核心链路，建立一套可直接执行的回归测试集。

本次重点覆盖五类高风险场景：

1. 单条检测链路
2. 批量任务上传与执行链路
3. 看板与任务记录的数据刷新链路
4. 结果复核与详情联动链路
5. 数据一致性与状态流转链路

当前测试优先级以 `P0/P1` 为主，优先保证“能演示、能跑通、结果一致、页面不误导”。

## 2. 假设与待确认项

### 当前假设

- 系统已具备可访问的 Web 前端与 API 后端。
- 单条检测支持普通检测与改写检测两种模式。
- 批量任务支持上传文本文件或表格文件后创建后台任务。
- 看板、任务记录、结果复核、系统状态页面均已接入真实接口。
- 当前正式同名结果基线为 `77` 条。

### 待确认项

- 批量任务上传当前到底支持哪些文件格式作为正式输入，是否统一为 `txt/csv/xlsx`。
- 单条检测与批量检测是否已经统一使用同一套候选展示阈值。
- 结果复核页中“确认高疑似 / 继续复核 / 排除”是否已经完整落库并支持回显。
- 任务取消、任务重试是否已经在前端完整暴露。

## 3. 测试点

### 功能流

- 单条检测能否正常提交、返回、切换候选、联动详情
- 批量任务能否正常上传、入队、执行、完成、导出
- 看板能否刷新后稳定显示真实数据
- 结果复核能否按选中行联动详情并保存复核结果
- 系统状态页能否展示真实运行状态

### 交互与前端体验

- 文件选择按钮是否可点击、可重复选择、失败后可重试
- 列表点击选中是否生效，是否必须依赖额外“查看”按钮
- 页面是否存在明显空白区、错位、滚动过长、加载阻塞
- 刷新后首屏是否先出列表，再补详情，而不是整页卡住

### 数据一致性

- 同一条文本在单条检测与批量检测中的候选展示口径是否一致
- 看板统计、任务记录、结果复核三处的数据是否互相对得上
- 任务完成后导出状态是否同步更新
- 结果复核后的标签是否能被再次查询和回显

### 异常与边界

- 空文本提交
- 超长文本提交
- 非法文件、空文件、损坏文件上传
- 任务执行中刷新、切页、重复点击创建
- 后端慢响应或失败时的前端提示

### 非功能

- 看板刷新性能
- 系统状态接口慢时的页面降级体验
- 大列表分页与首屏加载性能

## 6. 风险与缺口

- 当前最需要优先回归的不是底层算法，而是前端主工作流是否真正可用，尤其是文件上传、排队执行、详情联动、刷新体验。
- 单条检测与批量检测的候选展示阈值是否完全统一，仍然是一个高风险点，必须单独做口径一致性回归。
- 看板、任务记录、结果复核三处如果统计口径不一致，会直接削弱系统可信度，建议列为每轮回归必测项。
- 当前用例已覆盖主要高风险流程，但还没有拆到接口级字段校验、权限、浏览器兼容、长时间稳定性压测；这些适合在主流程稳定后继续补。
