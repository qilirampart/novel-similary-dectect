# TAPD需求草案：小说数据申请与相似度比对服务验证

更新时间：2026-04-28

## 1. 需求名称

小说数据申请与相似度比对服务第一阶段验证

## 2. 需求背景

当前 `侵权巡检助手` 已经具备视频链接采集、视频下载、音频提取、ASR 转写、字幕导出等能力，能够产出后续比对所需的字幕文本和时间轴数据。

法务相关场景需要将视频字幕结果与公司内部小说内容进行相似度比对，用于：

- 发现疑似改编内容
- 召回候选书籍和候选章节
- 定位具体命中文本证据
- 为法务或业务人工复核提供依据

本次需求的重点不是一次性完成全量巡检平台，而是先完成第一阶段的数据接入与能力验证，确认小说数据可接入、可清洗、可检索、可输出证据片段。

## 3. 需求目标

基于公司侧可提供的小说数据，先完成一版最小可行验证链路，打通：

`小说数据接入 -> 原始留档 -> 标准化清洗 -> 索引构建 -> 字幕提交 -> 候选召回 -> 证据输出`

第一阶段验证目标：

- 能拿到一批可用的小说数据
- 能完成原始文本下载和留档
- 能完成章节级数据清洗和标准化
- 能完成基础检索验证
- 能输出可复核的候选章节和命中片段

## 4. 当前已知前提

根据已沟通信息，当前已知情况如下：

- 数据范围先按：`自有 CP`
- 内容范围先按：`超短 + 中短`
- 预计数据量级：`GB 级，约 2GB 左右`
- 交付方式大概率为：`OSS 链接 + 文本文件`
- 若提供 OSS 链接，单次交付体积可能较小
- 当前可优先提供一版历史数据，用于第一阶段验证

## 5. 本次申请的数据范围

本次申请建议范围如下：

- 小说来源：自有 CP
- 小说长度范围：超短、中短
- 数据用途：相似度比对服务第一阶段验证

本次优先不追求一次性覆盖全部小说类型，先保证：

- 数据可获取
- 字段可识别
- 文本可处理
- 检索链路可跑通

## 6. 期望交付形式

优先希望提供以下形式之一：

### 方案 A：OSS 链接 + 对应信息表

每章正文一个文本文件，对应一份清单表。

### 方案 B：章节级正文文件 + 对应信息表

如果不走链接，也可以直接给章节级正文文件和信息表。

## 7. 最低字段要求

如走 `OSS 链接 + 信息表` 方式，信息表至少希望包含：

- `book_name`
- `chapter_name`
- `chapter_order`
- `oss_url`

如能补充以下字段，后续系统建设会更顺畅：

- `book_id`
- `chapter_id`
- `author_name`
- `updated_at`

## 8. 本次数据的使用方式

本次数据将仅用于内部研发验证，主要包括：

- 小说原始文本下载与原始留档
- 文本清洗与标准化处理
- 检索索引构建
- 相似度召回验证
- 命中文本证据片段验证

本次不用于对外提供，也不用于非本项目范围的业务用途。

## 9. 研发侧要做的工作

拿到数据后，研发侧计划按以下顺序推进：

1. 校验信息表字段与链接可用性
2. 批量下载原始文本并留档
3. 建立小说与章节的映射关系
4. 对正文做标准化清洗
5. 构建基础检索与比对链路
6. 用样本字幕验证召回与证据输出效果

## 10. 预期产出

第一阶段预计产出：

- 一版可用的小说数据原始层
- 一版标准化章节数据
- 一版基础索引与比对验证链路
- 一版候选章节与证据片段输出能力

## 11. 依赖与协作事项

本需求推进依赖以下配合：

- 数据提供方协助确认数据范围
- 数据提供方协助提供清单表或导出说明
- 如 OSS 链接存在有效期限制，需要协助说明失效周期
- 如后续需要增量同步，需后续再协商自动化方式

## 12. 风险说明

当前阶段的主要风险包括：

- 字段不足，导致章节与正文难以稳定映射
- 链接有时效，未及时下载可能影响验证
- 若缺少稳定 `book_id` / `chapter_id`，后续增量同步会变复杂
- 若仅能拿到零散文本而无清单表，后续清洗和索引成本会上升

## 13. 验收口径

第一阶段不以“全量上线”为验收目标，而以“链路跑通”为目标。

建议验收标准：

- 能成功接收一批目标范围内小说数据
- 能完成原始文本落地与清洗
- 能产出章节级标准化数据
- 能基于样本字幕召回候选章节
- 能输出可人工复核的命中文本片段
