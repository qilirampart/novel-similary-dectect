# 短剧字幕匹配 API 接入说明

## 用途与边界

本服务用于将待检测字幕与已入库的短剧字幕进行比对，返回是否命中、候选剧集、集数及双方时间证据。适合由采集、字幕下载或 ASR 工具调用。

桌面采集端只负责获取视频、字幕和来源信息；短剧字幕库、SQLite 词级索引、Qdrant 语义向量库、最终判定规则和复核记录均保留在服务端。接入方不得把“返回候选”直接写成命中结论，必须读取服务端 `decision`。

当前云端服务地址：`http://novel-similarity-dev.dzkjm.cn`。

## 调用顺序

1. 调用登录接口。服务端以 HttpOnly Cookie 维持会话，后续请求必须复用同一个 HTTP Session。
2. 单条实时判断调用 `POST /api/v1/drama-subtitles/compare`。
3. 多视频、多字幕片段使用批量任务接口；轮询任务详情直到终态。
4. 只依据 `payload.decision.status` 判断最终结果；需要人工查看时，再按 `window_uid` 拉取扩展证据。

`POST /api/v1/auth/login`

```json
{
  "username": "operator1",
  "password": "<password>"
}
```

成功后响应：

```json
{
  "user": {
    "user_id": 2,
    "username": "operator1",
    "display_name": "测试操作员",
    "role": "operator"
  }

```

认证信息通过响应 Cookie 返回。Python `requests.Session()`、Java `HttpClient` CookieStore、浏览器 fetch 的 `credentials: "include"` 均可保持会话。会话失效或未登录会返回 `401`。

## 单条检测

`POST /api/v1/drama-subtitles/compare`

```json
{
  "query_text": "待检测的字幕或台词文本",
  "language_code": "en",
  "top_k": 10,
  "window_limit": 200,
  "semantic_enabled": true,
  "semantic_window_limit": 100
}
```

字段说明：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `query_text` | 是 | 待检测文本。建议按字幕 cue 切为约 320 至 500 字符片段，并保留一条 cue 重叠。 |
| `language_code` | 否 | `zh`、`en`、`ja`、`ko`。传入后强制同语言检索；不传则自动识别。 |
| `top_k` | 否 | 内部候选数量，默认 10，范围 1 至 20。仅用于调试、复核。 |
| `window_limit` | 否 | 词级检索窗口数量，默认 200，范围 1 至 500。 |
| `semantic_enabled` | 否 | 默认启用同语言语义增强。关闭后仍保留词级检索。 |
| `semantic_window_limit` | 否 | 语义候选窗口数量，默认 100。 |

响应示例：

```json
{
  "request_id": "...",
  "duration_seconds": 3.24,
  "payload": {
    "mode": "hybrid_lexical_semantic",
    "query_language_code": "en",
    "semantic_status": "ok",
    "candidate_count": 10,
    "candidates": [],
    "decision": {
      "matched": true,
      "status": "matched",
      "outcome": "confirmed_match",
      "reason": "strong_lexical_evidence",
      "user_message": "已确认命中：检测文本与库内剧集存在充分的连续文本复用证据。",
      "candidate_rank": 1,
      "book_id": "42000017075",
      "book_name": "The Taming Game",
      "matched_episode_order": 1,
      "language_code": "en",
      "evidence_window_uid": "42000017075:1:1-16",
      "related_episode_orders": [2]
    }
  }
}
```

## 最终判定

`decision` 是唯一对外结论。`candidates` 是内部召回候选，不代表命中。

接入方优先展示 `decision.user_message`。`outcome` 用于向最终用户表达更具体的业务含义，`status` 与 `matched` 保持严格的接口语义。

为避免把“内容已发现”与“剧名已唯一确认”混为一谈，`decision` 还会返回两个独立字段：

| 字段 | 含义 |
| --- | --- |
| `content_match_status` | `matched` 表示已发现足够强的连续文本复用证据；`uncertain` 表示只有可疑证据；`not_matched` 表示未命中当前库。 |
| `title_resolution` | `unique` 表示可唯一确认剧名；`ambiguous` 表示多部剧均有强证据，无法自动指定唯一剧名；`unresolved` 表示证据不足；`not_applicable` 表示未命中。 |

当 `content_match_status=matched` 且 `title_resolution=ambiguous` 时，用户侧应显示“内容已命中，剧名待确认”，并展示 `user_message` 与 `strong_match_candidates`。这不是未命中，也不是普通低分候选；通常说明库内存在疑似同内容的不同标题或版本。

| `decision.outcome` | 用户侧建议文案 |
| --- | --- |
| `confirmed_match` | 已确认命中。 |
| `content_matched_ambiguous` | 已命中高重复内容，待确认剧名。 |
| `potential_match` | 发现可疑证据，待人工复核。 |
| `no_match` | 未命中当前库。 |

| `decision.status` | `matched` | 接入方动作 |
| --- | --- | --- |
| `matched` | `true` | 可作为确认命中候选，展示 `book_id`、`book_name`、集数和证据；仍建议保留人工复核。 |
| `review_required` | `false` | 不得写成命中。展示待复核原因和候选证据，进入人工核验。 |
| `not_matched` | `false` | 明确显示“未命中当前库”，不要因 Top10 中存在候选而改为命中。 |

常见 `reason`：

| 原因 | 含义 |
| --- | --- |
| `strong_lexical_evidence` | 词级复用证据达到确认阈值。 |
| `lexical_evidence_below_acceptance_threshold` | 有局部词级证据，但不足以自动确认。 |
| `semantic_candidate_requires_manual_review` | 仅语义相似度较高，必须人工查看。 |
| `multiple_books_with_strong_lexical_evidence` | 多部剧同时存在强证据，不能自动选择唯一命中。 |
| `no_candidate_above_acceptance_threshold` | 没有达到确认或待复核门槛的候选。 |
| `semantic_unavailable_no_lexical_evidence` | 语义服务降级且没有可确认词级证据。 |

确认命中依赖可解释的词级复用证据。英文按连续四词短语，中、日、韩文按字符三元词；语义分数只用于补充候选与触发待复核，不能单独确认侵权。

当 `reason` 为 `multiple_books_with_strong_lexical_evidence` 时，接入方应优先展示 `user_message` 和 `strong_match_candidates`。这表示“内容层面已经发现高重复证据，但库内有多个近似版本，暂不能自动确认唯一剧名”，而不是普通的未命中或低置信候选。对应 `outcome` 为 `content_matched_ambiguous`。

`strong_match_candidates` 已按复核优先级排序。每项包含 `book_name`、`book_id`、`matched_episode_order`、`aggregate_text_coverage_rate`（同集所有已召回窗口合并后的输入文本覆盖率）、`text_coverage_rate`（最佳单窗口覆盖率）、`matched_window_count`、`evidence_coverage_rate`、`semantic_score` 和 `review_priority`。接入方应优先展示排名靠前的候选，并同时展示累计文本覆盖率和语义相似度；排序始终以连续文本复用证据为主，语义相似度仅用于辅助区分同档候选。

## 候选和证据

`candidates` 中每个候选通常包含：

```json
{
  "rank": 1,
  "book_id": "42000017075",
  "book_name": "The Taming Game",
  "episode_order": 1,
  "language_code": "en",
  "retrieval_sources": ["lexical", "semantic"],
  "semantic_score": 0.93,
  "match_metrics": {
    "match_unit": "word_4gram",
    "match_unit_label": "共享四词短语",
    "shared_trigram_count": 80,
    "query_trigram_count": 281,
    "query_coverage_rate": 0.2847,
    "evidence_coverage_rate": 1.0,
    "shared_trigrams": []
  },
  "evidence": {
    "window_uid": "42000017075:1:1-16",
    "time_start": "00:00:00,000",
    "time_end": "00:00:40,000",
    "window_text": "..."
  }
}
```

需要更长的原剧证据时调用：

`GET /api/v1/drama-subtitles/evidence-context/{window_uid}?context_chars=2400&before_lines=6`

`context_chars` 范围为 600 至 5000。该接口只回查原始字幕上下文，不会重新执行召回，不影响批量吞吐。

## 批量任务

创建任务：`POST /api/v1/drama-subtitles/tasks`，使用 `multipart/form-data`。

| 表单字段 | 说明 |
| --- | --- |
| `file` | CSV、XLSX、TSV 或 TXT。建议 CSV 使用 UTF-8 with BOM。 |
| `top_k` | 可选，默认 10。 |
| `window_limit` | 可选，默认 200。 |
| `semantic_enabled` | 可选，默认启用。 |
| `semantic_window_limit` | 可选，默认 100。 |

CSV 最小字段：

```csv
source_ref,query_text
https://www.youtube.com/watch?v=VIDEO_ID#segment-1,待检测字幕文本
```

建议完整字段，用于溯源与后续维权导出：

```csv
source_ref,query_text,source_platform,source_display_title,source_description,source_video_id,source_channel,source_upload_date,source_caption_language,source_caption_source,source_segment_order,source_time_start,source_time_end,source_text_original
```

字段建议：

- `source_ref`：视频链接加片段编号。
- `source_video_id`、`source_channel`、`source_upload_date`：视频溯源。
- `source_caption_language`、`source_caption_source`：字幕轨道语言和来源，例如人工字幕、自动字幕或 ASR。
- `source_segment_order`、`source_time_start`、`source_time_end`：YouTube 侧字幕片段定位。
- `source_text_original`：未规范化的原始字幕，保留作证据。

创建响应：

```json
{
  "task_id": "uuid",
  "status": "queued",
  "source_file_name": "youtube_subtitles.csv"
}
```

查询详情：`GET /api/v1/drama-subtitles/tasks/{task_id}`。任务详情和任务列表现在会在 `task.queue` 中返回排队位置、前方任务/条目数与保守 ETA；创建响应保持不变。YouTube 等接入端应在现有轮询中读取该字段并显示“排队中”或“正在检测”，不要把排队过程视为黑盒。字段、状态和展示规则见 `93_短剧字幕批量任务队列API变更说明_2026-08-10.md`。

任务终态包括：`completed`、`partial_failed`、`failed`、`cancelled`、`paused`。客户端轮询时必须把 `partial_failed` 视为结束状态，并展示已完成与失败数量。

每个 `items[]` 条目包含来源字段、`duration_seconds`、`result_payload_json` 和最终命中字段。请解析 `result_payload_json.decision` 获取三态结论；仅 `decision.status == "matched"` 时，`matched_book_id`、`matched_book_name` 等字段才表示确认命中。

任务控制接口：

- `POST /api/v1/drama-subtitles/tasks/{task_id}/pause`
- `POST /api/v1/drama-subtitles/tasks/{task_id}/resume`
- `POST /api/v1/drama-subtitles/tasks/{task_id}/cancel`
- `DELETE /api/v1/drama-subtitles/tasks/{task_id}`

复核与导出接口：

- `POST /api/v1/drama-subtitles/tasks/items/{task_item_id}/review`
- `GET /api/v1/drama-subtitles/tasks/{task_id}/exports/review-xlsx`

复核状态可使用：`pending`、`confirmed_high_risk`、`needs_followup`、`false_positive`。

## 接入建议

对 YouTube 字幕工具，优先使用批量任务。每个视频按 cue 分段后上传，每段保留 YouTube 时间范围；服务端逐段返回判定，客户端再按 `source_video_id` 聚合。

视频级聚合应单独统计确认命中片段数、待复核片段数和未命中片段数。只有至少一个片段为 `matched` 时，视频级结果才能显示“确认命中”；只有待复核片段时，视频级状态应为“待人工复核”。

当前已部署并验证：短剧字幕 SQLite、4B Qdrant collection（309,138 points）、词级检索、同语言语义增强、三态判定、扩展证据读取和跨语言翻译回退。接入方仍应优先传入原始字幕语言；当原语言未形成可靠内容命中时，可通过 `translation_fallback: true` 启用翻译回退。翻译后候选会以 `translation_assisted_match` 和 `review_required` 返回，不能作为确认命中。具体字段与展示规则见 `91_短剧字幕匹配API跨语言翻译回退接入说明_2026-08-09.md`。
