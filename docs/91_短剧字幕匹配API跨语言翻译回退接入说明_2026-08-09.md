# 短剧字幕匹配 API 跨语言翻译回退接入说明

## 本次迭代

短剧字幕匹配服务已增加跨语言翻译回退能力，适用于输入字幕语言与库内同一内容的字幕语言不一致的场景。例如，待检测视频为英文字幕，而库内保留的是中文字幕。服务仍先按原语言完成词法与语义检索；只有原语言没有形成可靠的内容命中时，才将输入翻译为语料量更充足的目标语言并再次检索。

翻译只用于扩展召回，不能替代原字幕的直接证据。因此，翻译后找到的候选统一返回为“翻译辅助待复核”，不会自动返回“确认命中”。接入方必须继续以服务端的 `decision` 为唯一结论，不能将 Top1 候选或 `translation_candidates` 直接标记为命中。

本说明补充既有 [短剧字幕匹配 API 接入说明](87_短剧字幕匹配API接入说明_2026-08-05.md) 和 [API 变更摘要](88_短剧字幕匹配API变更摘要_2026-08-06.md)，重点说明本次新增行为。

## 适用接口

以下接口均支持本次能力，认证方式、Cookie 会话和原有参数保持不变。

| 接口 | 使用场景 | 新增参数 |
| --- | --- | --- |
| `POST /api/v1/drama-subtitles/compare` | 单段字幕实时检测 | `translation_fallback` |
| `POST /api/v1/drama-subtitles/video-compare` | 单个视频及其 cue 时间轴检测 | `translation_fallback` |
| `POST /api/v1/drama-subtitles/tasks` | 多条字幕批量检测 | 服务端默认启用，无需采集端逐条翻译 |

单段接口和视频接口新增的请求字段如下：

```json
{
  "query_text": "Subtitle text to compare.",
  "language_code": "en",
  "semantic_enabled": true,
  "translation_fallback": true
}
```

| 字段 | 是否必填 | 说明 |
| --- | --- | --- |
| `translation_fallback` | 否 | 是否允许在原语言未形成可靠内容命中时执行翻译回退。建议传 `true`。未传时遵从服务端当前默认配置。 |
| `language_code` | 否 | 建议由接入方在已知字幕轨语言时明确传入 `zh`、`en`、`ko` 或 `ja`，避免语言识别误差影响路由。 |

视频接口仍需完整的 `query_text` 与 `cues`。接入方无需为了翻译自行切分或分别调用多种语言，服务端会先完成原语言视频级判断，再在必要时执行一次回退检索。

## 回退策略

服务端根据输入语言选择语料更充足的目标语言，按顺序尝试并在首次得到候选后停止。

| 输入语言 | 翻译回退顺序 |
| --- | --- |
| 中文 `zh` | 英文 `en`，韩文 `ko` |
| 英文 `en` | 中文 `zh`，韩文 `ko` |
| 韩文 `ko`、日文 `ja` | 中文 `zh`，英文 `en` |

当前日文库内窗口数量很少，因此日文不作为默认翻译目标。原语言已得到 `content_match_status=matched` 时不会调用翻译；`no_match` 和低置信 `potential_match` 均可触发回退，避免不相关的弱候选阻断正确的跨语言召回。

服务端按“登录用户 + 原字幕内容 + 原语言 + 目标语言”隔离缓存译文。同一用户再次提交完全相同的文本时会直接复用译文，不会重复请求翻译服务。翻译缓存不会跨用户共享。

## 新增结果语义

翻译后检出候选时，`payload.decision` 会使用以下固定语义：

```json
{
  "matched": false,
  "status": "review_required",
  "outcome": "translation_assisted_match",
  "content_match_status": "uncertain",
  "title_resolution": "unresolved",
  "reason": "translation_assisted_candidate_requires_review",
  "user_message": "翻译辅助待复核：原字幕翻译为 zh 后发现候选。机器翻译不能单独作为确认依据，请核对原字幕剧情与候选证据。"
}
```

这组字段的含义是：服务发现了具有复核价值的跨语言候选，但不能据此直接确认同一剧集或侵权关系。接入方应显示“翻译辅助待复核”，并进入人工核验，不得显示“已命中”。

| `outcome` | 接入端展示与处理 |
| --- | --- |
| `confirmed_match` | 已确认命中，可展示剧名、集数和证据。 |
| `content_matched_ambiguous` | 内容已命中但剧名不能唯一确认，展示全部强证据剧名并进入复核。 |
| `potential_match` | 原语言存在可疑候选，进入复核。 |
| `translation_assisted_match` | 翻译后发现跨语言候选，显示“翻译辅助待复核”，进入复核。 |
| `no_match` | 未命中当前字幕库。 |

## 翻译回退字段

无论是否触发翻译，响应的 `payload.translation_fallback` 都会提供执行状态。接入端可用它展示补充说明和调试信息，但最终业务结论仍以 `payload.decision` 为准。

```json
{
  "enabled": true,
  "source_language_code": "en",
  "status": "matched",
  "matched_target_language_code": "zh",
  "attempts": [
    {
      "target_language_code": "zh",
      "provider": "deepl-free-v2",
      "cache_hit": false,
      "translation_duration_seconds": 0.82,
      "translated_text": "仅用于复核展示的译文",
      "outcome": "confirmed_match",
      "candidate_count": 3,
      "duration_seconds": 2.14
    }
  ]
}
```

| 字段 | 说明 |
| --- | --- |
| `status=not_needed` | 原语言已经形成可靠内容命中，未调用翻译。 |
| `status=matched` | 翻译后获得候选；此时外层 `decision.outcome` 必为 `translation_assisted_match`。 |
| `status=exhausted` | 已尝试可用目标语言，仍没有候选，最终保持 `no_match`。 |
| `status=unavailable` | 翻译服务未配置或暂不可用，原语言检索结果仍可正常使用。 |
| `attempts[].cache_hit` | `true` 表示译文来自当前用户的缓存；`false` 表示本次新请求翻译。 |
| `attempts[].translated_text` | 仅用于复核理解和问题排查，不能替代原始字幕留存。 |

视频接口在翻译命中时，另会返回：

| 字段 | 说明 |
| --- | --- |
| `payload.translation_candidates` | 使用译文召回得到的候选列表，包含剧名、集数、语言和证据窗口。 |
| `payload.translated_query_text` | 实际参与目标语言检索的译文。 |
| `payload.video_decision.decision_source` | 值为 `translation_fallback`，用于区别原语言视频级直接判定。 |

单段接口的 `payload.candidates` 在翻译命中时即为译文召回候选；应结合 `translation_fallback.matched_target_language_code` 理解其检索语言。

## 接入端展示建议

接入端应保留用户上传的原字幕作为主文本，不能用译文覆盖原文。对于 `translation_assisted_match`，建议在结果卡片或复核页依次展示：原字幕语言、检索使用的目标语言、候选剧名与集数、原字幕、译文和候选证据上下文。

`review_feedback` 中的 `title`、`summary` 和 `recommended_action` 为服务端生成的中文复核提示，应优先直接展示。候选证据若需要扩展上下文，继续调用原有接口：

`GET /api/v1/drama-subtitles/evidence-context/{window_uid}?context_chars=2400&before_lines=6`

该接口只读取已入库字幕上下文，不会再次执行检索或翻译。

推荐的聚合逻辑如下：只有至少一个片段为 `confirmed_match` 时，视频才可标记“确认命中”；存在 `translation_assisted_match`、`content_matched_ambiguous` 或 `potential_match`，但没有确认命中时，视频应标记“待人工复核”；所有片段均为 `no_match` 时，才标记“未命中当前库”。

## 性能与验证结果

翻译回退不会影响原语言已确认命中的正常路径。仅原语言未形成可靠内容命中时才增加翻译和目标语言检索开销；同文本重试将使用用户隔离缓存，避免重复翻译调用。

云端已完成真实跨语言视频级验证：英文字幕翻译回中文后返回 `translation_assisted_match` 并命中预期剧集；首次请求约 9.1 秒，译文缓存命中后的同请求约 1.9 秒。另以随机英文文本验证，两个目标语言均检索后仍返回 `no_match`，不会因翻译回退产生确认命中误报。

本次能力已部署到云端，接入方可直接在现有认证会话下传入 `translation_fallback: true` 使用。
