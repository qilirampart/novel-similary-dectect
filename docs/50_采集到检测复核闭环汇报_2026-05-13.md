# 从采集到检测复核的闭环汇报

更新时间：2026-05-13

这次可以把整条业务链路讲得比较清楚了。当前系统已经不只是“能跑一段相似度脚本”，而是把侵权线索采集、短剧台词提取、批量相似度召回、人工复核判断串成了一条可实际落地的工作流。

可以用一条“待检测作者的抖音主页链接”作为最典型示例来说明。

第一步，是通过采集软件输入目标作者的抖音主页链接。采集软件当前已经具备抖音主页级采集能力，可以批量提取该主页下可处理的短剧视频链接，并把这些链接送入后续下载与处理流程。这个阶段解决的是“从一个作者主页，快速拿到一批待分析短剧素材”的问题，避免人工逐条找视频、逐条复制分享链接。

第二步，是对采集到的视频做批量下载、音频提取和语音识别。当前采集软件已经具备视频下载、音频抽取、ASR 转写和结果沉淀能力，可以把原始视频转成后续可用于文本分析的台词内容。对于侵权巡检这个场景，我们现在重点使用的是短剧首集台词，因为首集通常最容易暴露核心剧情设定、人物关系和关键冲突，也是与小说原著建立初步证据链的高价值区段。

第三步，是把转写结果导出为 Excel。导出的表不是简单把一堆字幕文本堆在一起，而是会保留和溯源相关的关键信息，包括短剧名、集数、作者、平台、分享链接、展示标题、描述以及整段字幕全文。这样导出的结果既能作为检测系统的批量输入，也能作为后续复核和法务判断时的原始证据来源。

第四步，是把这份 Excel 直接导入我们的相似度检测系统。当前检测系统已经兼容采集软件导出的这类表格格式，不需要人工再做一轮复杂清洗。系统会自动识别短剧名、集数、作者、分享链接和字幕全文，并将每一条样本拆成独立任务进入后台批量检测队列。也就是说，采集侧导出的结果现在已经能无缝进入检测侧，而不是靠临时转换脚本才能跑。

第五步，是检测系统做批量召回。系统会对每条短剧台词先做粗召回，再进入精排比对，并输出命中书名、命中章节、证据级别、精排分数、语义状态和单条耗时等结果。当前系统默认支持改写检测链路，在语义能力可用时会走更完整的召回路径；如果语义侧暂时不可用，也会自动降级到词法链路，保证批量任务不会因为单点能力波动直接中断。

第六步，是进入结果复核。当前复核页已经按这个业务场景做过一轮收敛，核心视角不再是单纯看一条“文本命中了哪本书”，而是把“短剧名、集数、作者、查询台词、命中小说、候选文本、证据指标、分享链接”等信息放在同一视野里，方便直接判断这一条短剧台词与库中小说是否存在高风险关联。换句话说，前面采集和检测产出的信息，现在已经能在复核页形成一条完整证据链，而不是分散在多个系统和多个表格里。

如果用一句话概括当前能力，可以理解为：我们已经可以从一个待排查作者的抖音主页出发，批量提取其短剧首集视频，自动转成台词文本，导出标准化 Excel，再把 Excel 直接送入小说相似度检测系统做批量召回，最后在复核工作台上完成人工判断。这样就把原本分散、依赖人工拼装的巡检动作，收敛成了一套可重复执行的内部闭环。

这条链路的价值主要体现在三个层面。

第一，是效率提升。以前如果想验证某个作者主页下多部短剧是否涉嫌改编或侵权，需要人工逐条找视频、逐条听台词、逐条整理文案，再手动做比对。现在从主页采集到批量召回已经可以串起来，人工主要集中在最后的结果复核和判断阶段。

第二，是证据留痕更完整。过去很多问题不是比不出来，而是比出来之后难以回溯“这条结果对应的是哪部短剧、哪一集、哪个作者、哪条原始链接”。现在这些溯源字段已经贯穿采集、导出、导入、检测和复核链路，后续不管是做法务说明、内部复盘，还是二次补查，都更容易对上原始来源。

第三，是后续扩展空间已经打开。当前我们先以“作者主页 -> 首集台词 -> 批量召回 -> 复核”作为最小可用闭环跑通，后面如果需要扩大样本范围，可以继续往下扩成整剧多集检测、片段级检测、不同平台导入、批量结果归档和专项台账输出。也就是说，现在不是一个孤立 demo，而是已经有继续工程化推进的基础。

不过也要把当前阶段的现实约束说清楚。现在系统链路本身已经基本跑通，但真实覆盖范围仍然明显受制于底层小说数据是否充足。我们已经把业务线索表中“中台可查=是”的原著小说做过一轮系统性交叉核验，当前正式确认有 77 条是“中台可查且我们数据库里已有”的结果，其中有 26 条还保留了可直接用于真实比对的首集台词，能够作为当前最有价值的一批实测样本继续推进。

与此同时，线索表里还有 740 条虽然标记为“中台可查”，但在我们当前数据库以及两份源数据表里都找不到对应书名。这个结论很重要，因为它说明当前问题的重点已经不是“导入链路是否稳定”或者“是不是导入时漏了”，而是现有源数据本身覆盖不足。也就是说，我们现在已经具备了从采集、转写、批量检测到复核的完整能力，但如果后续希望扩大真实测试样本、提升线索覆盖率、减少“业务说中台可查但系统查不到”的情况，核心动作不是继续修导入，而是补充更多小说源数据或中台数据。

当前更适合对外或对内统一表述为：

我们已经打通了一条面向短剧侵权巡检的端到端链路。以待检测作者的抖音主页为入口，采集软件可以批量提取主页下短剧首集视频，自动完成下载、音频提取和台词识别，并导出带短剧名、集数、作者、分享链接和字幕全文的标准化 Excel。检测系统可以直接接收这份 Excel，自动拆分批量任务并执行小说相似度召回，最终在复核工作台中把短剧台词、命中小说和溯源信息集中展示，支持人工完成最终风险判断。整条链路已经从“素材采集”延伸到了“检测与复核”，形成了可重复执行的内部闭环。当前正式确认有 77 条是中台可查且数据库已有的有效样本，其中 26 条还保留了可直接比对的真实台词，可作为现阶段核心测试样本继续推进；同时还有 740 条虽然在线索表中标记为中台可查，但并不在我们当前数据覆盖范围内，因此下一阶段的关键不是继续修导入，而是补充更多小说源数据，进一步扩大系统可验证的覆盖面。
