## Phase 2：字幕窗口化

本轮窗口化参数如下：

- 每窗最大行数：`16`
- overlap：`6`
- 最小窗口行数：`6`
- 最大字符数：`500`

窗口化目标不是把整集字幕拼成长文本，而是保留“能用于复核定位的局部证据块”。每个窗口保存了：

- `book_id`
- `book_name`
- `episode_order`
- `line_start`
- `line_end`
- `time_start`
- `time_end`
- `window_text`
- `window_text_preview`

## Phase 3：首版 lexical 检索

本轮 lexical 方案没有先接向量，而是先落最轻的一版可运行底座：

- 目标表：`drama_subtitle_windows`
- 索引方式：SQLite `FTS5`
- tokenizer：`trigram`

这样做的原因很直接：

1. 中文台词本身连续度强，`trigram` 很适合做首轮词法召回
2. 当前阶段先验证“字幕窗口是否可检索”比直接上语义更重要
3. 这一步可以作为后续 lexical + semantic 融合召回的第一层

### 全量索引结果

全量运行命令：

```powershell
python scripts\build_drama_subtitle_lexical_index_v1.py --db data\drama_subtitle_similarity_v1.sqlite3 --output-root data_samples\middle_platform_subtitles_20260722_phase3 --overwrite
```

全量结果：

- 源窗口数：`309198`
- 已建索引行数：`309198`

### 检索验证

这说明当前“字幕窗口 -> trigram lexical 检索”这条链路已经跑通，不再只是规划阶段。
