# 批量 Compare 评估与初版阈值建议

## 1. 本轮评估目的

这轮不是在验证“语义洗稿”能力，而是在验证当前这条 V1 链路：

- 全库统一粗召回
- 候选章节现切
- 细比对打分
- 证据等级标注

是否已经足够稳定，能先把“明显的原文重合 / 几乎整句命中”这类结果可靠地找出来，并把弱相关结果压下去。

## 2. 评估口径

- 数据集：`self_short_novels`
- 查询集：`data_samples/retrieval_eval/self_short_eval_queries_canonical_v1.csv`
- 样本量：`200`
- 查询来源：从目标章节正文中截取固定长度片段
- 目标：验证目标章节在细比对阶段是否仍排第 1，以及非自身候选是否被稳定压低

这是一轮“自检式评估”。

它更适合回答两个问题：

1. 当前 exact / near-exact 文本命中链路是否稳定
2. 当前细比对是否已经能把弱相关候选分数明显拉开

它还不能回答“语义改写、AI 洗稿”场景下阈值应该怎么定，因为这批评估样本本身不是改写样本。

证据等级分布：

- 弱相关候选普遍低于 `0.08`

## 4. 现阶段可以怎么用

### 4.1 适合先落地的能力

当前最适合先落地的是：

- 找“整句复用”
- 找“长连续片段复用”
- 找“同一段话基本原样搬运”

也就是先做一个“强证据发现器”。

这对侵权初筛已经有实际价值，因为它能先把最容易解释、最容易人工确认的一类结果稳定打出来。

### 4.2 现在还不适合直接承诺的能力

当前还不应该直接承诺：

- 语义改写后的稳定识别
- AI 洗稿后的高召回
- “字面变化很大，但意思高度一致”的可靠判定

因为这需要单独构造改写评估集，或者引入后续向量化 / 语义模型路线来验证。

## 5. 初版阈值建议

基于这轮结果，当前可以先给出一版偏保守的工作阈值。

### 5.1 强证据

建议判为“强证据”的条件：

- `exact_substring_hit = true`
- `longest_match_ratio >= 0.95`
- `fine_score >= 0.90`

解释：

- 这基本意味着“查询片段几乎整段连续出现在候选窗口里”
- 对人工复核最友好
- 误报风险最低

### 5.2 弱证据

建议直接判为“弱证据”的条件：

- `fine_score < 0.10`

解释：

- 本轮 200 条样本里，第一条非自身候选最高也只有 `0.0734`
- 所以在当前 exact / near-exact 口径下，`0.10` 以下基本可以视为弱相关或场景词碰撞

### 5.3 中证据

当前不建议急着把“中证据”用于自动业务判断。

原因很简单：

- 这轮评估集中没有真实的“中间态正样本”
- 也就是说，我们还没有一批“不是原句照搬，但确实存在较强相似”的标注数据来校准这个档位

所以当前更稳妥的做法是：

- `强证据` 先用于高优先级结果
- `弱证据` 先用于直接降权
- `中证据` 先保留为待校准档位，不作为自动结论

## 6. 对后续工作的意义

这轮结果说明三件事：

1. 当前 V1 文本链路已经可以稳定抓住“原句级 / 长片段级”重合
2. 当前细比对已经能把弱相关候选和真命中明显拉开
3. 下一阶段最值得投入的不是继续打磨 exact 命中，而是补“改写 / 洗稿”评估集，开始校准语义相似路线

## 7. 下一步建议

下一步建议按这个顺序推进：

1. 先人工挑一批“疑似洗稿 / 改写”样本，形成小规模标注集
2. 用这批样本复跑当前 compare 链路，看 `中证据` 是否真的覆盖有效样本
3. 如果覆盖不足，再决定是否引入向量化召回或语义重排

这样推进比较稳，因为每一步都能回答一个明确问题，而不是直接把系统复杂度拉上去。
