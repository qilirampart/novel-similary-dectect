# 云端封面巡检首轮发布记录

## 发布结论

2026 年 9 月 14 日，封面巡检模块完成首轮云端发布。当前生效 release 为 `20260914-cover-frontend-live-1`，原 release `20260904-first7-qdrant-telemetry-1` 及本轮各级候选均保留为回滚点。切换前已创建业务 SQLite 一致性备份，切换后 API 服务恢复 `active`，readiness 检查通过；独立 `novel-similarity-cover-worker.service` 已安装并保持 `active/running`，启动后重启次数为 0。

本轮只开放项目隔离的 `local` 封面存储，数据库、正式资产、staging、导入和导出目录均位于 `/opt/novel-similarity-service/shared/runtime/cover_monitor`。封面文件不会进入 release，也不会随版本复制。OSS 适配能力已经随代码发布，但在完成 RAM 权限、私有 Bucket 和生命周期规则验收前，不切换为 OSS 活动后端。

## 发布过程

发布前修复了两个运维隐患。部署检查不再读取或输出 systemd 的 `Environment` 属性，避免运行日志泄露环境变量；前端构建增加限定在 `web/dist` 的逐文件清理和结果校验，历史哈希资产由约 30 MiB、140 个文件收敛为当前页面实际引用的 3 个文件，其中两个静态资产合计 467,913 字节。候选 release 的目录替换只允许安全相对路径，并通过 `realpath` 拒绝越界或符号链接路径。

候选 release 在未激活状态下完成完整性检查：后端、服务和脚本共 219 个文件，前端恰好 3 个文件。共享 Python 虚拟环境增量安装了 Pillow、yt-dlp、阿里云 OSS SDK 及其依赖；安装采用项目专属代理 `127.0.0.1:17890` 和官方 PyPI，未卸载或降级已有包。安装后 `PIL`、`yt_dlp`、`alibabacloud_oss_v2` 均可导入，现网 API 安装前后持续健康。

候选切换前执行了 API 导入和 worker `--once` 空轮询冒烟。正式切换通过受控激活器完成：先备份业务库，再修改 `current`、重启 API 并等待 readiness；若任一步失败，脚本会自动恢复旧 release、重启并重新检查健康。本次切换成功，未触发回滚。

## 真实小流量验收

使用 `待处理频道1.xlsx` 验收时发现原文件为无表头、单列频道 URL，首版导入器要求频道名和频道链接表头，因此预览返回 `400`，没有确认导入或创建任务。服务端随后增加了仅限 `channels` 类型的保守兼容：首行只有一个非空值且可解析出合法 `UC...` 频道 ID 时，识别为无表头单列文件；频道名临时使用频道 ID，采集后再由平台信息补全。真实文件本地复核为 50/50 行有效、50 个唯一频道、0 缺失。

热修上线后，同一文件成功导入 50 个频道元数据，并只对频道 `UCX8oe3DG5lg7FYWguvuGW0Q` 创建最多 10 个视频的标准强度任务。任务 ID 为 `47563200-fb55-48ac-841f-0a96096cf15b`，10/10 检测成功、0 条失败，总耗时 35.403 秒，平均约 3.54 秒/条；结果为 7 条安全、3 条待复核。新增检测 Excel 成功导出，文件大小 14,555 字节。

该任务因主动设置 10 条采集上限，频道完整性正确标为 `partial`，后端批次状态保持 `partial_failed` 以避免误称全量扫描完成，但不存在项目失败。前端已调整为：`failed_item_count=0` 时显示“部分完成”，存在实际失败时才显示“部分失败”。

发布复核还发现 Nginx 的实际静态根目录是 release 下的 `web-dist`，而初始候选误上传到 `web/dist`，导致后端已更新但公网仍引用旧资产。最终候选改为受控替换 `web-dist`；公网登录页已引用 `index--JgailBz.js`，脚本返回 `application/javascript`、364,225 字节，旧哈希不再出现。该路径已同步修正到候选验收脚本。
