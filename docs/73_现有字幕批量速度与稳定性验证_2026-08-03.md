# 现有字幕批量速度与稳定性验证

## 测试方式

从 `data/drama_subtitle_similarity_v1.sqlite3` 抽取 26 条真实字幕窗口，生成带视频 ID、片段序号、字幕语言、时间范围和原始台词的批量 CSV。测试使用临时业务数据库，实际执行短剧批量任务的输入解析、词法召回、结果持久化和任务完成状态，不影响现有任务数据。

同一批数据连续执行两轮，用于检查任务稳定性和召回结果一致性。

## 测试结果

| 指标 | 第 1 轮 | 第 2 轮 |
|---|---:|---:|
| 输入条数 | 26 | 26 |
| 完成条数 | 26 | 26 |
| 失败条数 | 0 | 0 |
| 成功召回条数 | 26 | 26 |
| 总耗时 | 77.3226 秒 | 77.1057 秒 |
| 平均单条耗时 | 2.9629 秒 | 2.9539 秒 |
| 最短单条耗时 | 2.3022 秒 | 1.8484 秒 |
| 最长单条耗时 | 4.4592 秒 | 5.3928 秒 |

两轮命中的 `bookId` 集合均为 `41000100291`、`41000100292`、`41000105381`，结果集合完全一致，任务状态均为 `completed`。

## 结论

在当前本地字幕库和词法召回链路下，26 条字幕批量任务可以稳定完成，没有出现任务失败、结果漏保存或两轮召回不一致。当前实际吞吐约为 `0.34 条/秒`，按当前串行短剧任务执行方式，100 条约需 5 分钟，500 条约需 25 分钟，实际时间会随台词长度和数据库负载变化。

本次测试说明稳定性没有明显问题；如果后续需要提高批量吞吐，应优先将短剧任务项检索做受控并行，同时继续保持任务项独立保存、暂停/取消检查和失败项可追踪，不能直接以无边界并发替代现有 worker 流程。

可复现脚本：`scripts/benchmark_existing_subtitle_batch_v1.py`
