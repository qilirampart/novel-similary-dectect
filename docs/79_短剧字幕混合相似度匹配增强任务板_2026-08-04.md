# 短剧字幕混合相似度匹配增强任务板

## 当前判断

4B 语义 collection 已完成全量回填，Qdrant 与 SQLite 同步状态均为 309138 条。现有短剧字幕单条接口和批量执行器仍只调用词级 FTS 检索；语义检索目前只存在于独立脚本，尚未进入用户实际使用的检测链路。因此下一阶段的目标是完成安全的混合召回，而不是继续扩充向量数据。

词级检索继续承担精确复用、英文连续四词短语命中和证据高亮；语义检索只用于同语言的改写补召回。向量相似度不能直接替代词级分数，更不能在未验证的情况下把弱语义候选排到明确复用证据之前。

## 目标链路

输入字幕 -> 语言识别 -> 词级候选 Top20 -> 同语言语义候选 Top20 -> 按剧集与集数合并 -> 保留最佳证据窗口和来源 -> 稳健排序 -> 单条、批量、复核与导出展示。

语义服务、Qdrant 或 embedding API 异常时，结果必须自动回退到词级检索，并在结果中返回明确的降级状态和原因。批量任务不能因单条语义调用失败整体失败。

## 实施原则

第一版不依赖 reranker。先完成 H1-H4：词级候选保留原有相对优先级，语义候选仅补充词级没有召回的剧集，或作为同一剧集的附加来源和证据。这样可以先获得改写召回增益，又不会把未经验证的向量分数变成最终裁决。

语义查询使用当前 4B collection `drama_subtitle_window_embeddings_qwen3_4b_2560_v1`，只在 `zh`、`en`、`ja`、`ko` 四种已建索引语言内查询，并强制携带 Qdrant `language_code` filter。`unknown` 输入只走词级链路并标记为“语义未启用：语言不可路由”。

接口层需显式保留 `retrieval_sources`、`best_lexical_score`、`semantic_score`、`semantic_status`、`semantic_error`、`query_language_code`、`duration_seconds` 等字段。证据高亮仍以词级共享片段为准；语义候选没有可靠字面重合时，只展示“语义补充”而不伪造高亮。

## 当前下一步

进入 H5：在短剧检测页面和批量结果中展示词级、语义和混合来源，展示语义降级原因与每条耗时；证据高亮仍以可解释的词级重合为准。
