# V1数据库表结构草案

更新时间：2026-04-28

这版只保留当前开工必要的表，不做过重设计。

## 1. 目标

当前表结构只解决四件事：

- 记录导入批次
- 记录书和章节元数据
- 记录下载状态和原始文件路径
- 为后续清洗、切分、检索留出落点

## 2. 当前建议表

### `ingest_batches`

记录一次数据导入批次。

核心字段：

- `batch_id`
- `source_file_name`
- `source_file_sha256`
- `source_row_count`
- `created_at`

### `books`

记录书级元数据。

核心字段：

- `book_ext_id`
- `book_name`
- `chapter_count`
- `total_char_count`
- `avg_chapter_char_count`

### `chapters`

记录章节元数据和下载状态。

核心字段：

- `chapter_id`
- `book_ext_id`
- `chapter_name`
- `chapter_order`
- `url_host`
- `object_key`
- `signed_url`
- `signed_expires_at`
- `downloaded_at`
- `download_status`
- `download_error`
- `raw_file_path`

### `chapter_contents`

记录正文三个版本。

核心字段：

- `chapter_id`
- `content_raw`
- `content_clean`
- `content_retrieval`

### `semantic_chunks`

记录 `600-1200` 字语义片段。

核心字段：

- `chunk_id`
- `chapter_id`
- `chunk_order`
- `start_offset`
- `end_offset`
- `content`

### `evidence_windows`

记录 `150-300` 字证据滑窗。

核心字段：

- `window_id`
- `chapter_id`
- `window_order`
- `start_offset`
- `end_offset`
- `content`

## 3. 当前文件

可执行 SQL 草案已落在：

- `service/schema_v1.sql`

## 4. 当前原则

- 先支持下载、落盘、清洗、切分
- 不先设计过多任务表和审计表
- 不先引入复杂权限模型
- 等第一版数据跑通后再补 compare / review 结果表
