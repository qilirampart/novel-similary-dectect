# 批量小说下载标准方案

## 目标

把后续任意一批小说 Excel 清单稳定下载到本地，并保证：

- 章节内容不写错文件名
- 不同数据批次不混目录、不混日志
- 支持断点续传
- 支持夜间长时间运行
- 对源端缺失章节单独留痕，不让整批任务卡死

---

## 本次已经验证过的方案

当前方案已经在两批数据上跑通过：

- `自有短篇小说.xlsx`
- `线上自有小说.xlsx`

已经验证过的关键能力：

- `manifest -> raw_rel_path -> txt文件` 的映射稳定
- 实际下载可以断点续传
- 队列可以先跑一批，再自动切下一批
- 对源端 `404` 可以单独标记后跳过
- 下载完成后可以做一致性校验：`expected=actual`、`extra=0`、`missing=0`

已经验证过的参数：

- `workers=32`
- `retries=2`
- `timeout=60`
- 进度监控刷新间隔：`180s`

## 核心原则

### 1. 先建清单，再下载

所有下载都必须先从 Excel 生成 `manifest.csv`，不要直接拿 Excel 边读边下。

原因：

- 先固化任务边界
- 方便断点续传
- 方便做一致性校验
- 方便后续追查某一章是否缺失、404、重复、错位

### 2. 一个批次一个目录

每个新表都必须独立一个 `batch_id`，目录结构固定：

```text
raw/<batch_id>/
  manifest/
    manifest.csv
    manifest_summary.txt
    原始xlsx副本
  txt/
    <book_ext_id>/<chapter_id>.txt
  logs/
    *.log
    download_results_*.csv
    latest_download_status.txt
    terminal_failures.csv
```

不能把不同来源的小说混到同一个 `batch_id` 里。

### 3. 落盘路径只认 manifest

最终文件路径必须始终由 `raw_rel_path` 决定，例如：

```text
txt/<book_ext_id>/<chapter_id>.txt
```

下载完成顺序可以乱，但文件名和目录不能乱。

### 4. 同一时刻只允许一个主下载器

切脚本、提并发、重启任务时，必须先停旧下载器，再启新下载器。

不能让两个主下载器同时接管同一个批次。

### 5. 404 要单独处理，不能无限重试

如果一批章节稳定返回 `HTTP 404`，要写入：

```text
raw/<batch_id>/logs/terminal_failures.csv
```

然后让队列继续往下走，不要被最后几百章卡住一整夜。

## 标准执行步骤

### 第一步：从 Excel 生成 manifest

命令：

```powershell
python scripts\build_manifest.py --xlsx "你的文件.xlsx" --batch-id batch_YYYYMMDD_xxx
```

检查点：

- `raw/<batch_id>/manifest/manifest.csv`
- `raw/<batch_id>/manifest/manifest_summary.txt`

重点看：

- `row_count`
- `unique_books`
- 原始 Excel 是否已复制进 `manifest/`

### 第二步：把批次加入下载队列

编辑队列文件，例如：

```text
raw/download_queue_20260428.json
```

格式：

```json
{
  "batches": [
    {
      "key": "dataset_key",
      "label": "Dataset Label",
      "manifest": "raw/batch_xxx/manifest/manifest.csv",
      "workers": 32,
      "retries": 2,
      "timeout": 60
    }
  ]
}
```

要求：

- `key` 要稳定、简短、可区分
- `label` 用于人看
- `manifest` 必须是显式路径

### 第三步：启动下载队列

命令：

```powershell
python scripts\run_download_queue.py --queue-file raw\download_queue_20260428.json --poll-seconds 180
```

作用：

- 轮询当前批次状态
- 如果下载器掉了，自动拉起
- 当前批次完成后，自动切到下一批

### 第四步：启动进度监控

命令：

```powershell
python scripts\watch_download_progress.py --manifest raw\<batch_id>\manifest\manifest.csv --interval-seconds 180 --quiet
```

主要看两个文件：

- `raw/<batch_id>/logs/download_progress_watch.log`
- `raw/<batch_id>/logs/latest_download_status.txt`

### 第五步：下载完成后做一致性校验

最终必须满足：

- `expected = actual`
- `extra = 0`
- `missing = 0`
- `chapter_path_issues = 0`

如果是本批次源端缺失，允许：

- `missing > 0`
- 但这些缺口必须全部进入 `terminal_failures.csv`

## 已验证的排错顺序

如果下载“看起来很慢”，按这个顺序看：

### 1. 看是不是状态文件滞后

先数真实 `txt` 文件数，不要只看 `latest_download_status.txt`。

### 2. 看是不是卡在固定 404

检查：

- `download_results_*.csv`
- `terminal_failures.csv`

如果最后一批一直 `downloaded=0 failed=N`，通常不是网络慢，是源端固定 `404`。

### 3. 看是不是旧锁残留

检查：

```text
raw/<batch_id>/logs/download.lock
```

如果下载器已停但锁还在，队列不会重新拉起新下载器。

### 4. 看有没有临时文件残留

检查：

- `*.part`
- `*.tmp`
- `*.partial`

如果只是当前时间点正在写的 `.part`，正常。
如果长时间不消失，再处理。

## 后续新小说表的执行口径

以后来新的小说 Excel，统一按下面这套口径执行：

1. 先单独建 `batch_id`
2. 先生成 `manifest.csv`
3. 单独建日志目录和状态文件
4. 加入队列，不和旧批次混目录
5. 下载完成后做一致性校验
6. 对固定 404 单独留痕
7. 再进入清洗、入库、切分

---

## 结论

后续小说下载继续沿用这套方案，不再重新摸索：

- `manifest先行`
- `批次隔离`
- `单主下载器`
- `队列接力`
- `404单独留痕`
- `最终一致性校验`

这就是后续小说批量下载的标准方案。
