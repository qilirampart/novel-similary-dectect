# 短剧字幕语义检索与重排实施规划

## 目标

在不替换现有词级短语检索的前提下，为短剧字幕检测增加同语言语义召回与精排能力。词级检索继续负责精确复用、可解释高亮和稳定基础召回；语义层负责补充同义替换、轻度改写和语序调整后的候选，并用重排降低泛题材误报。

本轮只作用于短剧字幕链路，不修改小说库已上线的 Qwen3-Embedding-8B 向量、collection 或 rewrite 检索逻辑。

## 当前基线

- 标准化字幕窗口：309198 条，覆盖前 10 集的可用字幕。
- 词级检索：中文、日文、韩文使用字符 trigram；英文使用连续四词短语。
- 本地 Qdrant 已存在旧试点 collection：drama_subtitle_window_embeddings_qwen3_8b_1024_v1，共 4365 点。
- 已确认 Qwen3-Embedding-4B 可通过 Gitee API 正常返回中英文 2560 维向量。
- 现有脚本已具备字幕窗口向量化、Qdrant upsert、SQLite 同步状态和断点续跑能力。

## 目标架构

输入字幕先按现有语言识别器确定原语言。词级层返回 TopN 精确短语候选；语义层仅在相同语言 collection 内检索 TopN 窗口。两侧结果按 book_id + episode_order 聚合、去重，再调用 reranker 对有限候选精排。最终仍返回原始字幕窗口、时间范围和词级高亮证据。

候选流程：

输入字幕 -> 同语言词级短语候选 -> 同语言向量候选 -> 合并去重 -> reranker 精排 -> 证据窗口与复核展示

API、Qdrant 或 reranker 异常时，系统返回现有词级结果，并明确标记为“语义增强暂不可用”；不得阻塞批量任务或把失败伪装成无命中。

## 数据与 collection 隔离

- 新 collection：drama_subtitle_window_embeddings_qwen3_4b_2560_v1
- 模型：Qwen3-Embedding-4B
- 向量维度：2560
- 距离：Cosine
- 点 ID：复用窗口稳定 UUID，collection 维度保持独立。
- payload 必须包含：window_uid、book_id、book_name、episode_uid、episode_order、language_code、时间范围、行范围、文本预览、模型名和维度。
- 小说 collection、旧短剧 8B collection、新短剧 4B collection 严格分离，任何查询均不得跨 collection 或混合不同模型向量。

按 float32 估算，309198 条 2560 维原始向量约 2.95 GiB；考虑 HNSW 索引、WAL 和 payload，应在全量前确认本机 Qdrant 数据盘至少预留 8 GiB 可用空间。

## 分阶段实施

### 阶段一：语义索引可用性

先完成 S1-S2。现有向量化脚本的 payload 需要补充 language_code，语义查询需要在 Qdrant 侧携带同语言 filter。此阶段只创建新 collection 和新的同步状态，不修改正在使用的短剧词级结果，也不把新 collection 写入前台默认配置。

### 阶段二：小样本质量闸门

先从有明确来源的字幕窗口抽取试点样本，并构造三类评估：

- 从同一窗口裁剪出的原文片段，检查 TopK 是否回到正确剧集和集数。
- 对原文做人工可控的同义替换、词序微调，检查语义层是否补回词级层遗漏的候选。
- 使用同语言但不同题材的干扰文本，检查候选是否被泛化为“总裁、离婚、婚姻”等题材相似。

同时用已采集的 YouTube 完整字幕抽样人工复核。该数据没有完整金标，不得把“返回 Top1”写成准确率；只记录人工确认的正确、待定和错误候选。

小样本通过条件不是固定单一分数阈值，而是：同语言过滤正确、精确复用不弱于词级、改写样本出现有效增益、无关干扰不出现系统性高排，以及 API 吞吐与失败率可接受。

### 阶段三：全量回填

S5 通过后再执行 S6。全量任务使用独立进度文件、较小起始 batch 和可恢复同步状态。先测 4、8、16 条批量请求的 API 吞吐和错误率，再固定稳定批次。每批成功写入 Qdrant 后才更新 SQLite 同步状态；中断后按 collection、模型和维度继续，不重做已成功窗口。

全量结束后必须核对：

- collection 维度为 2560；
- Qdrant points_count 与同步状态窗口数一致；
- 各语言点数与字幕窗口语言分布大致一致；
- 随机窗口检索可返回对应 payload 与原始证据；
- Qdrant 磁盘占用、WAL 和查询延迟在可接受范围内。

### 阶段四：混合召回与精排

S7 不直接以向量分数覆盖词级排序。初版策略为：

- 词级 Top20 与语义 Top20 取并集；
- 按剧集聚合，保留每个剧集的最佳证据窗口；
- 对合并后的有限候选调用 Qwen3-Reranker-0.6B，前提是单独完成模型可用性、输入上限、费用和稳定性探测；
- 输出词级短语覆盖、语义分数、reranker 分数和最终排序来源；
- 精确短语强命中优先保留，语义结果主要补齐词级未召回或低覆盖的改写候选。

### 阶段五：前台和发布

批量和单条结果需展示“词级命中”“语义补充”“精排后”的来源状态。语义 API、Qdrant 或 reranker 任何一项失败时展示降级提示，但不影响任务进度和词级结果。发布顺序为本地完整回归、云端新 collection 灰度、云端样本验证、再切换默认增强开关；保留仅词级模式作为一键回滚路径。
