# 短剧字幕纯词法主链启动记录

## 当前决策

短剧字幕匹配先以词法召回作为正式开发主线，语义向量化后置补做。这个决策不会影响短剧字幕数据标准化、窗口化、词法候选、证据定位、后续批量任务或前端复核的开发。

语义向量仅用于补足改写、同义替换和低字面重合场景，并不是基本匹配能力的前置条件。当前库已经有 309,198 个字幕窗口的 FTS5 trigram 索引，能够直接支持中文连续台词的快速候选检索。

## 已接入能力

新增服务模块：

```text
service/drama_subtitle_retrieval.py
```

新增受登录保护的单条接口：

```text
POST /api/v1/drama-subtitles/compare
```

请求字段：

```json
{
  "query_text": "待比对字幕文本",
  "top_k": 10,
  "window_limit": 200
}
```

接口返回独立的短剧字段，包括 `book_id`、剧名、命中集数、检索窗口数、词法得分、字幕行范围、时间范围、字幕摘要和完整证据文本。它不调用小说 `/api/v1/compare/single`，也不读取小说章节或小说结果表。

## 验证

对真实查询“`大哥这是横店吗你们是不是在拍戏`”，服务层返回：

- `41000010048 / 农女致富 / 第 1 集`
- 证据时间：`00:00:12,720` 至 `00:00:51,920`

回归测试 `tests/test_drama_subtitle_retrieval.py` 已通过，覆盖：

- 重叠窗口聚合为同一剧集候选
- 少于三字时的 `LIKE` 回退

## 语义索引状态

短剧向量化脚本和独立 Qdrant collection 已完成小样本验证，但全量回填暂不继续。启动后的上游 embedding API 出现 `502 Bad Gateway`，同时当前产品开发可以先依赖词法主链，因此将其调整为后置工作。

已有的向量同步状态和已写入窗口会被保留。API 稳定后重新运行相同脚本即可从断点续跑，不会重复写入已同步窗口。

## 下一步

在词法单条接口的返回结构基础上，新增短剧批量任务、结果持久化、任务筛选和专用复核页面；这些数据模型将与小说检测结果完全隔离。
