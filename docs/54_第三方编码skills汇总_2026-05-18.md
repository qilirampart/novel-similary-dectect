# 第三方编码 Skills 汇总

本文档汇总当前已放入本地项目目录的两套第三方编码 skills，便于后续给其他编码项目按需装载。

## 1. Addy Osmani Agent Skills

GitHub 地址：

`https://github.com/addyosmani/agent-skills`

简要介绍：

这是一套偏完整工程流程的编码 skills，核心定位不是单条规则，而是一整套围绕开发生命周期组织起来的工作流框架。它更适合需要规范化推进的编码项目，强调从 spec、plan、build、test、review 到 ship 的全流程约束，也包含前端、API、调试、性能、CI/CD 等多个方向的通用工程技能。

更适合的场景：

- 中大型编码项目
- 需要较强流程约束的项目
- 希望把需求拆解、实现、测试、复核、发布标准化的项目

- skills 目录：`E:\点众\小说库相似度比对服务工作区\third_party\agent-skills\skills`
- agents 目录：`E:\点众\小说库相似度比对服务工作区\third_party\agent-skills\agents`
- 说明文件：`E:\点众\小说库相似度比对服务工作区\third_party\agent-skills\README.md`

建议装载方式：

- 如果目标项目支持按目录装载 skills，优先使用 `skills` 目录
- 如果目标项目支持 agent / persona，也可以一并参考 `agents` 目录
- 这套更适合作为“流程框架”使用

## 2. Andrej Karpathy Skills

GitHub 地址：

`https://github.com/multica-ai/andrej-karpathy-skills`

简要介绍：

这是一套偏轻量的通用编码护栏，核心是四条 Karpathy 风格的行为原则，用来约束编码代理常见的问题，包括：先假设后编码、过度设计、顺手改动无关代码、没有明确验收标准就开工。它不是完整流程框架，更适合作为所有编码项目都能复用的“底层行为规则”。

核心原则：

- Think Before Coding
- Simplicity First
- Surgical Changes
- Goal-Driven Execution

更适合的场景：

- 所有类型的编码项目
- 需要先加一层通用编码行为约束的项目
- 希望降低误改、过度设计和无目标开发的项目

当前本地位置：

- 仓库根目录：`E:\点众\小说库相似度比对服务工作区\third_party\andrej-karpathy-skills`
- Claude 风格规则文件：`E:\点众\小说库相似度比对服务工作区\third_party\andrej-karpathy-skills\CLAUDE.md`
- Cursor 规则文件：`E:\点众\小说库相似度比对服务工作区\third_party\andrej-karpathy-skills\.cursor\rules\karpathy-guidelines.mdc`
- 可复用 skill：`E:\点众\小说库相似度比对服务工作区\third_party\andrej-karpathy-skills\skills\karpathy-guidelines\SKILL.md`
- 说明文件：`E:\点众\小说库相似度比对服务工作区\third_party\andrej-karpathy-skills\README.md`

建议装载方式：

- 如果目标项目是 Claude 风格规则体系，可优先参考 `CLAUDE.md`
- 如果目标项目是 Cursor，可优先使用 `.cursor/rules/karpathy-guidelines.mdc`
- 如果目标项目支持 skill 文件，可直接使用 `SKILL.md`
- 这套更适合作为“通用编码护栏”使用

## 3. 两套 Skills 的建议关系

如果其他项目只想先快速加一层通用编码约束，优先装载 Andrej Karpathy Skills。

如果其他项目已经进入较复杂的工程推进阶段，需要更完整的流程框架，再叠加 Addy Osmani Agent Skills。

简单理解：

- `andrej-karpathy-skills`：偏底层行为护栏
- `agent-skills`：偏上层工程流程框架

两套不是互斥关系，很多编码项目适合同时参考，但角色不同。
